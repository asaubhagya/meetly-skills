# Review project and task changes

Select the authorized Space and inspect its project, task and commitment links. Fetch cited original evidence for each proposed issue. Keep the distinction between a promise, a suggested follow-up, a decision and a completed task. A recording date is insufficient to infer a deadline. Preserve the recorded timezone and ask about ambiguous relative dates. Verify the owner against the destination team's users. Leave unresolved values unset.

Discover destination team, project, workflow states and fields. For Linear, map the chosen Meetly project to an existing or explicitly requested Linear Project and actionable work to Issues. Use scoped existing mappings before searching for duplicates by project, evidence and title. When a task and a commitment refer to one action, show both sources in a single proposed issue. Retain matter scope and require separate export approval for privileged fields.

Preview the team/project, issue action, changed fields, evidence references, ownership and dates. Obtain the user's approval for this set. Refresh matches before creation. On an uncertain response, look up the destination record through its mapping or unique key before retrying. Read back the external IDs, links and states. Request authorized Meetly reconciliation using the source revision and provenance. Keep a partial-success receipt for each record so a failed reconciliation can resume without creating a second issue.
